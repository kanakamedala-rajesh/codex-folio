# Community launch after source publication

These are recommended follow-up tasks, not visibility blockers.

## Explain the working workflow

Lead with profile selection, source-attributed usage evidence, and repository
checkpoints. Do not claim to be the only Codex usage tool. Do not promise unlimited
usage, bypassed restrictions, or zero context loss. Keep the independent-project
statement and your own visual identity.

Record a short real CLI demonstration using synthetic identities and repositories.
Label simulated provider responses. Show one useful flow and one unavailable-data
state. Label dashboard concepts as design previews, not implemented screenshots.
A public browser demo must use fixtures and must not contact a visitor's local
Codex service or request credentials.

## Make feedback useful

Start with a small group of developers who already need the supported workflow.
Give them concrete setup, usage-inspection, checkpoint, error-recovery, and
uninstall tasks. Record voluntary feedback about successful first use and repeat
use. Do not add telemetry simply to measure a launch.

Keep one maintained README or documentation destination and one feedback route.
Use accurate repository topics such as codex, codex-cli, cli, developer-tools,
local-first, usage-monitoring, and golang. Add a homepage only when it exists.
GitHub Discussions, a separate website, Discord, sponsors, and multiple package
managers are optional and introduce maintenance work.

Share technical explanations in communities whose current rules allow project
sharing. A runnable preview should precede a Show HN submission. Do not solicit
votes, invent testimonials, or promote the tool in unrelated support issues.
When a qualified binary release exists, replace the developer-only README build
path with the verified user installation path.

## Useful first issues

Prefer bounded CLI help, sanitized documentation, and focused fixture or error-case
tests. Each issue should name the expected behavior, files to inspect, test command,
and acceptance criteria. Keep authentication, vault, migration, and checkpoint
privacy changes under experienced maintainer review.
