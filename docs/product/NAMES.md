# Naming shortlist

This is a preliminary collision check, not trademark or legal clearance.

## Earlier recommendation

**VS CodexHarbor** with CLI command `vsharbor`.

The harbor metaphor fits persistent Identity Homes, safe arrival and departure, and a single local dashboard. A narrow web and GitHub search found no obvious exact software-project collision. The public description should say:

> VS CodexHarbor — an independent, local-first profile launcher and usage dashboard for Codex.

Public materials should visibly state that the project is not affiliated with or endorsed by OpenAI.

The user did not accept this as a final name: `vsharbor` loses the direct relationship to Codex and does not describe identity switching and aggregated usage clearly enough. It remains only a temporary brainstorming label.

## Revised naming requirements

- Retain an obvious relationship to Codex in both product and CLI names.
- Suggest identity selection, multiplexing, continuity, or aggregated usage.
- Remain distinct from the existing `codex-as` prototype.
- Avoid implying an official OpenAI product.
- Be concise enough for frequent terminal use.

## Revised shortlist

### Adopted working name: VS CodexFolio

CLI command: `codex-folio`

“Folio” describes a portfolio of Codex identities, work contexts, and usage views. The executable retains an obvious Codex relationship and remains suitable for frequent terminal use.

> VS CodexFolio — switch local Codex identities and see usage in one place.

A narrow current search found no obvious exact software, GitHub, or package collision. The name and command are adopted for planning, subject to release-time package, domain, and trademark checks.

### Other viable candidates

- **VS CodexFleet** (`codex-fleet`): strong multi-profile dashboard metaphor, but may imply team account pooling.
- **VS CodexPassport** (`codex-passport`): strongest identity metaphor, but weaker usage-dashboard meaning.

### Names rejected after collision checks

- `CodexMux`: exact collision with an existing Go CLI for switching Codex account profiles.
- `CodexSwitch`: multiple existing projects with nearly identical switching scope.
- `CodexHub`: several existing gateways, telemetry tools, and extensions.
- `CodexDeck`: active Codex-to-Stream-Deck project.

## Alternatives

1. **VS ProfileDock** (`vsdock`): vendor-neutral and extensible, but can be mistaken for a VS Code utility.
2. **VS CodexRoster** (`vsroster`): strong profile metaphor, but `Roster` is already used by an identity/routing product with Codex integration.
3. **VS Account Atlas** (`vsatlas`): broad analytics metaphor, but `Atlas` is crowded across software products.
4. **VenkataSudha Codex Relay** (`vsrelay`): emphasizes continuity, but `Relay` is crowded in AI tooling and an existing package already launches Codex with a local UI.

Avoid `Continuity` and `Switchboard`; both already have visible Codex-adjacent usage.

Before release, repeat checks across GitHub, package registries, executable names, domains, and applicable trademark databases.
