# Use per-launch loopback dashboard authorization

Accepted for the user-approved #106 certificate-warning follow-up. The user explicitly approved replacing persistent browser trust with a fresh one-time access URL on each ordinary launch, so opening the dashboard requires no certificate installation. This supersedes [ADR 0036](0036-remember-explicitly-trusted-browsers.md) for the default browser flow; its historical qualification evidence remains historical.

Keep private CLI commands on authenticated, certificate-pinned loopback TLS. Serve the browser dashboard on a separate ephemeral loopback HTTP listener, with no private command access. Ordinary startup prints a fresh single-use authorization URL without opening a browser. Put the bootstrap credential in the URL fragment, remove it from the address bar before exchange, and exchange it for a short-lived, in-memory server session. The browser keeps its session token in tab session storage and supplies an explicit request header; HTTP authorization must not use cookies, local storage, persistent browser trust, or automatic renewal across service restarts. A consumed link or old bookmark cannot authorize a new owner. Re-running the ordinary command or `service start` obtains a fresh link.

Preserve strict loopback binding, Host/Origin checks, no cross-origin access, CSRF, restrictive CSP, replay rejection, bounded requests, and server-side credential/vault custody. HTTP does not authenticate a local server to the browser and is not a defense against arbitrary malicious local processes. This tradeoff avoids durable ambient browser credentials being offered to a later process on a reused address; it does not weaken pinned TLS identity for private CLI traffic. Do not silently import certificates or bypass browser certificate errors.

Existing HTTPS trust support and stored records may remain for compatibility, but cannot authorize the default HTTP dashboard. `service certificate` remains public metadata for the private CLI certificate; browser certificate import is no longer an onboarding step. An upgrade ends the old default reopening guarantee: users obtain a fresh terminal URL after restart. Verify the fresh browser flow without certificate overrides, bootstrap replay and restart rejection, transport separation, and hostile request controls. Native/live qualification gaps remain separate from automated or Chrome DevTools MCP evidence.
