# Use a modular monolith with deep external seams

CodexFolio will ship as one executable and one user-scoped state owner while organizing behavior into feature-owned deep modules. Ports and adapters exist only at true external seams such as installed Codex, platform facilities, persistence/vault, browser transport, and optional remote endpoints; pure domain behavior remains concrete and local. The service owns writable durable state, but the CLI owns the foreground Codex child after receiving a validated Launch Plan, preserving terminal and signal behavior without competing database writers. This architecture provides production isolation and testability without the deployment and interface overhead of microservices or a ceremonial interface-per-type clean architecture.
