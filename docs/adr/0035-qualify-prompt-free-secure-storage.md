# Qualify prompt-free secure storage

Milestone 5A ([specification #82](https://github.com/kanakamedala-rajesh/codex-folio/issues/82), decisions 6–8 and 19; contract ticket #83) makes routine switching possible without repeated CodexFolio passphrases on qualified secure-storage configurations. This partially supersedes [ADR 0008](0008-use-a-tiered-encrypted-credential-vault.md): WSL is no longer assigned a passphrase-only default, explicit plaintext compatibility fallback is no longer permitted, and manual per-session unlock is not the everyday path on qualified configurations. ADR 0008's encrypted application key and OS-user protection rationale remains intact.

The required qualification matrix is Windows AMD64 with user-scoped DPAPI, macOS ARM64 with Keychain, Linux AMD64 with supported Secret Service in an available user session, and WSL2 with a qualified Windows-backed vault integration. Arbitrary headless systems without supported secure storage are outside the prompt-free guarantee. Explicitly chosen passphrase protection remains available, with its locked-after-restart behavior and sensitive-collection restrictions; it is not evidence of prompt-free qualification. Missing prerequisites must lead to guided setup or recovery in plain startup, never silent plaintext, adjacent local-key storage, or another protection downgrade.

The WSL integration belongs behind the existing vault boundary and protects the application key under the interoperating **Windows user's** protection context. It does not establish a separate Linux-user security boundary or isolation from processes able to act as that Windows user. Check Windows interoperability and storage prerequisites, including availability to the detached companion. Secrets must not appear in helper arguments, environment variables, URLs, logs, or browser responses. A successful foreground helper call or cross-compilation cannot establish qualification: native Windows-user protection, unavailable/wrong-context failures, migration, detached operation, and reopening after WSL/environment restart require evidence. This is an implementation obligation, not an already-qualified bridge.

Existing passphrase users receive guided migration with one final old-passphrase unlock. Preserve profiles, history, other retained state, Identity Homes, and Codex-owned credentials. Destination protection is successful only after existing protected data reopens through it. Failure or interruption must retain a recoverable prior protected state; never overwrite existing encrypted data with replacement key material to hide a failure. Do not silently copy or rewrite Codex credentials.

[ADR 0025](0025-encrypt-sensitive-sqlite-fields-through-the-vault.md) remains binding: sensitive paths, checkpoints, and recovery metadata stay envelope-encrypted, credentials never enter SQLite, and user-only filesystem protection remains required. The service remains the sole durable-state writer. Convenience does not bypass safe state ownership or identity checks. The mandatory real two-identity restart evidence in [EC-08](../product/ACCEPTANCE-CRITERIA.md#everyday-companion-milestone-5a) cannot inherit prior milestone exceptions. Review this successor contract before dependent runtime implementation; ticket #83 changes documentation only.
